# 四词单音识别（上 / 下 / 左 / 右）方案实测报告

> 2026-11-07 · 实验台 `F:\DeepSeek Harness\项目\单音识别方案`
> 目标：只说 4 个单音节词，直接输出 4 类；越轻量、越准确越好；优先纯浏览器离线。

> **⚠️ 2026-11-08 重要更新（真人录音实测后）**
> 下面 1–6 节的 TTS 结论只对 TTS 成立。用真人录音复测发现：
> **TTS 模板库换真人声音只有 20.8%**，自训小 CNN 4.2%，sherpa KWS 37.5%——轻量端侧方案在真人语音上全部不可用。
> **不需要校准、直接可用的通用方案**是 `server/` 里的 **Vosk + SenseVoice 双模型后端**：
> 真人 24 条 **24/24 = 100%**、TTS 72 条 72/72、legacy 48 条 48/48，HTTP 端到端 p50 111 ms。
> 详见第 7 节。浏览器 demo 仍保留（TTS 上 97.2%），但**真人使用请走 server 后端**。

---

## 0. 一句话结论

**没有哪个通用 ASR 值得为 4 个单音节词去跑。**
最优解是「**MFCC + DTW + 内嵌多音色模板库**」：61 KB 模板、零模型下载、纯前端 4 ms 一条，
在 6 个**训练时从未出现**的 TTS 音色（含东北/陕西口音、台湾腔）上 **97.2%**；
老人说「看不清/看不见/不知道」时 **18/18 正确归为 unsure**，不会误判成方向；
再花 30 秒录 4 个方向各 2 遍做校准，**同说话人 100%**。

如果允许保留 Python 后端，**Vosk 中文小模型 + 四字硬语法** 在 clean/白噪/窄带下都是 **100%**，
但模型 68 MB、误唤醒 12.3%、浏览器不可行——留给「电脑 + 局域网」的部署形态。

## 3. 关键发现

### 3.1 四个单音节根本不需要「先转文字再映射」

全量 ASR 的问题不是精度（SenseVoice 在 SAPI 单字上是 48/48），而是：
228 MB 模型 + 4 核 CPU + 376 ms 端到端延迟，而且噪声下掉到 79–85%。
把任务收缩成「4 类最近邻」后，61 KB 的模板就能在**没见过的口音音色**上做到 97.2%。

### 3.2 「跨说话人」不是靠单模板，是靠多音色模板库

同一个词、换一个音色，单个模板的 DTW 只有 **76.7%**（实测，模板=Yunxi 测其余 5 音色）。
但把 5 个训练音色各出一条模板、取最小距离后，**同一批测试集升到 97.2%**；
每词 25 条模板（全部 5 档语速）是 98.6%。
**结论：模板库的「音色多样性」比「模板数量」更重要。**

### 3.2b 现场校准（4 方向 × 2 遍）同时解决准确率和误接受

| 模式 | 四词准确率 | 正样本/负样本距离比 | 其它单字误接受 |
|---|---|---|---|
| 免校准模板库 | 97.2% | 1.33×（0.1275 vs 0.1691） | 39.9% |
| **现场校准 k=2** | **100%** | **4.8×**（0.0305 vs 0.1466） | **3.6%** |

校准后声学区分度直接拉开 3.6 倍，所以**误接受问题也一起解决了**（阈值取 `1.5×类内最大距离`）。
自动标定公式（demo 已内置）：每词录 k 条、两两 DTW 取词内最大值，
`maxWithin = max(4 个词)`；安静环境用 `1.5×maxWithin`、有噪声用 `2.0×`，`maxWithin > 0.12` 提示重录。
本语料实测 `maxWithin = 0.0561`，推荐阈值 ≈ 0.084。

### 3.3 加一个「看不清」类，产品风险直接归零

纯距离阈值拒不掉「看不清/看不见/不知道」——它们是多音节，但会被 DTW 强行对齐成某个方向
（保持 97.2% 准确率的阈值下，误判率 89%）。加入 15 条 train 音色 unsure 模板后：

- 四词准确率不变：97.2%
- 「看不清」18/18 判为 unsure（100%）
- 静音/噪声 100% 拒绝
- 代价：其它随机单字仍会被判成方向（44–69%，但实际流程里没人会说「多/错/小」）

这是老人视力筛查里最常见的回答，**必须做进模板库**。

### 3.4 单音节关键词 KWS：召回上不去，误唤醒反而很低

sherpa-onnx 中文 KWS（WenetSpeech 3.3M，int8 三件套 4.8 MB）在 4 个单字上的实测：

- 官方默认阈值 `0.25` 只有 33% 准确率；最优 `score=1.0, thr=0.02` → **80.6%**
- 逐类：上 94% / 下 94% / 右 83% / **左 50%**
- 反直觉的是**误唤醒从未超过 1.7%**——2 个 token 的单字并没有疯狂误触发
- 加噪声反而更高（84–92%）——干净短音频的尾部 padding 截断更伤
- **「左」的天花板找到了**：把同一套 onnx 当普通流式 transducer 贪心解码（不换模型），
  输出里「左」是 `suǒ`/`zuǒ`/`zuò` 混着来，`右` 有 2/3 音色啥都解不出。
  关键词写的 `z uǒ` 对不上 `s uǒ`——**s/z 声母混淆是模型能力问题，调参无解**，
  要提升只能换更大模型。

浏览器侧：sherpa-onnx 官方**不发** KWS 的预编译 wasm（issue #3112），要自己用 emsdk 编；
第三方 `@sherpaw/kws` 预编译 wasm 12.5 MB + int8 模型 4.8 MB，首屏 ~17.5 MB。
体积能接受，但 80.6% 的召回让它不值得。

### 3.5 Vosk 硬语法：精度冠军，但代价是 68 MB + 12% 误唤醒

`KaldiRecognizer(model, 16000, '["上","下","左","右","[unk]"]')`：

- clean / 白噪 20-10 dB / 粉红 / 窄带 **全部 100%**
- 去掉 `[unk]` 后误唤醒从 21.7% 飙到 **58.3%** —— `[unk]` 是命门
- 剩下的 12.3% 误唤醒是**系统性同韵母混淆**：多/错 → 左、小 → 下、少 → 上；
  「右」零误唤醒
- **词表级联**：只把 8 个声学近邻字（多 小 少 错 大 是 啊 我）加进语法当独立类别，
  误唤醒从 21.7% 压到 **1.5%**，准确率 100% → 95.8%（掉的 4.2 点全在「左」）；
  加到 20 个字没有额外收益。注意：级联和置信度阈值**不能叠加**（会双重惩罚）
- 68.3 MB + Kaldi FST → 浏览器不可行
- 许可证保留意见：官方模型页标 Apache-2.0，但模型 zip 内没有 LICENSE 文件，
  上生产前建议向 Alpha Cephei 书面确认

### 3.6 自训小 CNN：TTS-only 跨音色泛化不够

75K 参数 DS-CNN，int8 约 74 KB，训练 100 条 + 强增强。
v1：dev 93.2%，但 6 个未见音色上 **68.1%**（right 只有 33%），10 dB 白噪 0%。
v2 修正了「训练噪声只加语音段、评测加整段」的口径错位并改了窗口对齐，
当前 demo 里的权重换成 v2：clean **79.2%**、left 38.9%、FA 17.4%——仍**远低于模板库 97.2%**。
（注：v2 的 10 dB 90.3% 是训练/评测噪声口径对齐后的结果，不代表真实抗噪能力。）
结论：**TTS 的 5 个音色撑不起说话人无关的判别模型**，要可用必须补真人录音；
但 2 ms 延迟 + 74 KB 体积说明「补 20–50 条真人样本微调」是最省力的下一条路线。

## 4. 推荐落地（已做成 demo）

**纯浏览器、离线、单页**：`demo/index.html`

```
三种模式：
 1. 内置模板库（免校准，默认）  61 KB int8 模板，打开即用，TTS held-out 97.2%
 2. 我的校准模板（更准）        4 方向 × 2 遍 ≈ 30 秒，同说话人 100%
 3. 内置小模型（实验性）        75K CNN，不推荐，仅作对照
判决：5 选 1 最近邻（up/down/left/right/unsure）
      top1==unsure → 「看不清 / 没听清」
      mean 距离 > 0.25 → 「没听清，请再说一遍」
      mean = 每帧每维平均平方距离 = DTW 代价 / (n+m) / 26
性能：单条识别 p50 4.2 ms（Node 同量级），模板 61 KB，JS 全部 < 100 KB
```

实现要点：

- 前端纯 JS 实现 MFCC（25 ms/10 ms、n_fft 512、40 mel、预加重 0.97、逐句 CMVN），
  与 Python 参考实现 **max abs diff < 1.9e-5**（`demo/test_parity.mjs` 可复跑）
- 模板 int8 量化（每模板 scale），base64 内嵌，反量化后准确率与 float32 完全一致
- 麦克风：按住说话 + 能量 VAD 自动断句；也支持上传/拖入 wav（无麦克风权限也能测）
- 校准模板存 localStorage，可导出/导入/清空
- **首屏总载荷 196 KB**（HTML 10 KB + CSS 15 KB + JS 110 KB + 模板 61 KB），完全离线、无任何外部请求

## 5. 已知限制与下一步

### 真人录音接入步骤（工作台已备好，随时可跑）

1. 工作台录完 → `python corpus/build_corpus.py --manifest`（录音会进 `split=real`）
2. `python harness/bench.py --engines dtw_bank` → 自动多打一行 `[real] n=… acc=… FA=…`
3. **真人阈值不要直接沿用 TTS 的 0.18**：TTS 干净、d1 p50 只有 0.1275，真人 + 普通麦克风会整体上移。
   先用「不拒识」跑 top1 和 d1 分布（`python engines/dtw.py eval --thr-abs 1e9 --thr-margin=-1e9`），
   再把阈值定在 d1 p95 附近；demo 现在用 0.25 是合理起点。
4. 如果真人 top1 明显低于 97%，先查录音链路（16 kHz？单声道？有没有 AGC/降噪改了频谱），
   而不是调 DTW。
5. 真人现场校准：`python engines/dtw.py regcal` 重写 `results/dtw_registration.json`，
   里面的 `max_within` 就是 `1.5×maxWithin` 公式的输入；真人 maxWithin 大概率大于 0.0561，
   `>0.12` 的重录提示正好用上。
6. 如果想把小模型也跑起来：`python train/finetune.py --epochs 15 --lr 3e-4`
   （自动混 TTS 防遗忘并覆盖 `demo/model/` 权重），然后 `python harness/bench.py --engines tinycnn` 复测。

1. **真人语音还没验证**：以上全部是 TTS 语料（虽然跨 6 个音色 + 2 种口音 + 台湾腔）。
   `workbench/` 已经做好：录 24 条（上/下/左/右 各 6 遍，2 分钟），
   录完直接进 `split=real`，我会单独报一行真实准确率，并可用于微调小模型。
2. **噪声/窄带是短板**：20 dB 95.8%，10 dB 84.7%，窄带 70.8%。近场按键说话没问题，
   远场/助听器/老式电话需要重新采真实数据做增强。
   补充：`engines/dtw_bank.py` 用「原始含噪整段（不做 VAD）」跑出来的数字更低
   （clean 93.1%、10 dB top1 25%），因为噪声会让能量去静音失效、DTW 被迫对齐整段底噪。
   两个口径都成立，但**都别当成「低噪环境可用」的证据**——10 dB 下门控只能救回一部分，
   噪声大时请调小 maxDist、让用户重复一遍，或加校准（校准后区分度 4.8×，更抗噪）。
3. **免校准 97.2% 不是 100%**：错的两条都是 up↔down。老人用建议现场校准一次（30 秒）。
4. **误接受**：静音/噪声为 0，但其它随机单字会被判成方向；产品上靠「按键说话 + 只提示四个方向
   + 看不清类」规避，不建议做成常开唤醒。
5. **下一步最值得做**：用工作台采 10–20 位老人的真实语音 → 训练/微调一个说话人无关小模型，
   目标把免校准做到 99%+，彻底去掉校准步骤。

## 7. 真人语音实测（2026-11-08）与免校准后端方案

### 7.1 真人录音把 TTS 结论推翻了

用工作台录了 24 条真人样本（同一人，4 词 × 6 遍，16 kHz 单声道，1–3 秒/条）：
Vosk 转写确认内容正确（20/24 直接转对，另外 4 条两个模型互补后也全部可识别）。

| 方案 | 体积 | 真人 24 条准确率 | 说明 |
|---|---|---|---|
| TTS 模板库（浏览器 demo 默认） | 61 KB | **20.8%** | TTS→真人域差异，同词距离 6.6 vs 本人模板 2.5 |
| 自训小 CNN（74 KB int8） | 502 KB | 4.2% | TTS-only 完全失效 |
| sherpa-onnx KWS（4.8 MB） | 4.8 MB | 37.5% | 单音节关键词上限 |
| 现场校准 DTW（每词 2–3 遍） | ~70 KB | 91.7% | 但用户明确不希望做语音校对 |
| **Vosk small-cn + 四字硬语法** | **65 MB** | **83.3%** | 免校准 |
| **SenseVoice int8（拼音映射）** | **228 MB** | **75.0%** | 免校准 |
| **Vosk + SenseVoice 双模型（推荐）** | **293 MB** | **24/24 = 100%** | 免校准，错误完全互补 |

结论：**「轻量 + 纯浏览器 + 免校准 + 准确」四个条件目前无法同时满足**。
凡是能在真人语音上工作的，都是「真实人声训练」的 ASR（65 MB 起）；
4.8 MB / 74 KB / 61 KB 这些端侧方案在真人语音上只有 4%–37%。

### 7.2 推荐落地：`server/` 双模型后端（免校准）

```
Vosk small-cn（65 MB，四字硬语法） ─┐
                                   ├─ 融合判决 → 上/下/左/右/看不清/再说一遍
SenseVoice int8（228 MB，兜底）   ─┘
```

判决规则：Vosk 给出方向就用 Vosk；Vosk 没给出而 SenseVoice 精确命中 `shang/xia/zuo/you`
就用 SenseVoice；两者冲突取高置信度；出现「看不清/看不见/不知道」→ unsure；其余拒识。

实测（本机，R5 5600，4 线程）：

| 指标 | 结果 |
|---|---|
| 真人 24 条（HTTP 端到端） | **24/24 = 100%**（both 14 / vosk 6 / sensevoice 4） |
| TTS test/single 72 条 | 72/72 = 100% |
| legacy SAPI 48 条 | 48/48 = 100% |
| 「看不清」18 条 | 18/18 判为 unsure |
| 推理延迟 | 服务端 p50 102 ms（Vosk ~35 + SenseVoice ~60），HTTP 端到端 p50 111 ms / p95 151 ms |
| 模型加载 | 1.5 s |

启动方式：

```powershell
cd "F:\DeepSeek Harness\项目\单音识别方案\server"
python app.py            # 或双击 start_server.bat
# 打开 http://127.0.0.1:8088/  （按住说话 / 上传 WAV）
```

### 7.3 仍需注意
1. **只有 1 个人的 24 条真人录音**：100% 是小样本结果，必须再采几位老人/方言复测。
2. 真实噪声/远场下 Vosk 会漏检，SenseVoice 会听错——双模型互补能救一部分，但不保证 100%。
3. 负样本（其它单字）仍会被 Vosk 硬语法塞成方向（约 25%）；产品流程只提示四个方向 + 看不清，影响有限。
4. 浏览器 demo 的定位改成「离线 / TTS 演示」；真人使用走后端。若将来坚持纯浏览器，
   只能上 65 MB 的 Vosk WASM（83%），或先用公开真人语料训一个小模型（见第 5 节第 5 条）。

### 7.4 纯 HTML 离线版（Vosk + WASM，已验证）

给 Android / 无后端场景做的纯前端版本，在 `demo-wasm/`：

| 项 | 结果 |
|---|---|
| 组成 | `index.html` 15 KB + `vendor/vosk.js` 5.5 MB（WASM+Worker 单文件）+ `model.tar.gz` 41.8 MB |
| 离线首屏 | **47.4 MB**，无任何网络请求 |
| 真人 24 条 | **20/24 = 83.3%**（与 Python 版 Vosk 失败的完全同 4 条） |
| TTS 12 条 | **12/12 = 100%** |
| 合计 36 条 | 32/36 = 88.9% |
| 模型加载 | 首次 1.2 s，缓存后 0.5 s（IndexedDB） |
| 单条识别 | 130–350 ms（桌面 Chromium） |

实现细节与 Android WebView 打包方式（`WebViewAssetLoader`、assets 放置、权限、内存）见
`demo-wasm/README.md`。**能力上限就是 Vosk 单模型 83.3%**；要 100% 必须加 SenseVoice，
只能走 Android 原生（sherpa-onnx Kotlin）或保留 Python 后端。
