# 架构与代码地图

> 改代码前先看这一页，再决定要不要读 `index.html` 的某一段。
> 为什么这么设计看 [设计与决策.md](设计与决策.md)；算法出处看 [WHOeyes-逆向分析.md](WHOeyes-逆向分析.md)。

## 1. 整体形状

```
index.html                  一个文件装下 CSS + 10 个页面 + 全部业务逻辑
├── <style>                 14 – 306    设计变量 + 组件 + 各页面样式
├── <!-- 页面 -->            307 – 583   10 个 <section class="screen" data-screen="…">
├── <script src="voice/engine.js">  584  经典脚本，挂 window.VoiceEngine
├── <script>                585 – 1910  全部业务逻辑（16 个分区，见下）
└── <script type="module">  1911 – 1916 只做一件事：import 手势模块并挂 window.GestureEngine

voice/engine.js   语音模块封装（Vosk WASM、VAD、16 kHz 单音语法）
gesture/engine.js 手势模块封装（MediaPipe Hand、骨架绘制、object-fit 映射）
gesture/hand_rules.js    21 点 → 上/下/左/右
gesture/gesture_gate.js  动作激活 / 保持 400 ms / 每题一次 / 冷却
tools/*.py        syntax_check.py（内联脚本语法自检）、make_icons.py、cap_table.py（上限表）
```

**为什么手势用 module、语音用经典脚本**：MediaPipe 只发 ESM；Vosk 的封装是 UMD 风格，用经典脚本最省事。
`type="module"` 天然 defer，所以手势引擎在 DOM 就绪后才挂上，主脚本里要判断 `window.GestureEngine` 是否存在（懒加载）。

### 3.3 `session` 字段

```js
session = {
  type,            // 'distance' | 'near'
  distM,           // 米
  eyes: [...],     // 远距两只眼、近距只测双眼
  eyeIdx,          // 当前眼
  cap,             // maxRenderableIndex(distM)，本机上限档位
  group,           // 第几组（显示在 HUD）
  trials,          // 总题数
  results: {},     // { right|left|both: { logMAR, decimal, snellen, atCap, worse } }
  continuousMode,  // 语音/手势开着 → 每题后 1 秒缓冲
  trialsLog: [],   // 逐题明细，直接进历史
  aborted, paused,
  // 运行期：
  resolve,                 // 当前题的作答 Promise 回调
  questionShownAt,          // 出题时间（250 ms 内不接受作答，防抢答）
  continuousLockUntil,      // 1 秒硬缓冲截止时间
  lastRender,               // { size, stroke, frame, gap, devRaw, k, snapped, logMAR }，debug 用
}
```

### 3.4 历史记录结构

```js
{ ts, type,
  results: { right|left|both: { logMAR, decimal, worse, atCap } },
  trials,
  log: [ { eye, group, level, dir, ans, correct, at } ]   // 逐题明细（v0.9 起才有）
}
```

## 4. 一次测试的数据流

```
点击「开始测试」(data-action="setup-start")
  └─ startSession()                       ← 建 session、算 cap、开唤醒锁、按设置启动语音/手势
       ├─ showScreen('test')                ← 显示答题条
       └─ for 每只眼:
            ├─ countdown(3,2,1) + speak()   ← 「右眼测试，请遮住左眼」
            ├─ runEye()
            │    ├─ runLevel(level)         ← 一组 5 题
            │    │    ├─ pickDir() → drawOptotype(dir, level)   ← 画视标，记录 questionShownAt
            │    │    └─ getAnswer()        ← SIM 模式：simulateAnswer()；真实模式：waitAnswer()
            │    │         └─ answer(dir)   ← 唯一作答入口：闪按钮、开 1 秒锁、resolve
            │    │    └─ 答完 1 秒缓冲（continuousMode 时）→ answerGap()
            │    ├─ 通过（对 4）→ level += 2（封顶到 cap）
            │    └─ 失败 → 首次记 firstFail，退到 F-1 复测；再失败定档 F-2
            └─ intermission()            ← 换眼，5 秒倒计时自动继续
       └─ finishSession()
            ├─ 写 vs.history（含逐题 log）
            ├─ renderResult()            ← 三种记法 + 分级 + 建议
            └─ speak('测试完成…')
```

**关键契约**（改动时别破坏）：

- `drawOptotype()` 是唯一决定视标物理尺寸的地方，它同时写 `session.lastRender`。
- `answer()` 是**唯一**作答入口：点击、滑动、键盘、语音、手势全部走它，所以 1 秒锁和按钮闪烁只写一遍。
- `runLevel()` 只返回 `{pass}` / `{aborted}`；定档逻辑全在 `runEye()`。
- `session.cap` 在会话开始时算一次，整个会话不再变。

## 6. AI 模块接入点

| 方向 | 入口 |
|---|---|
| 主 → 语音 | `window.VoiceEngine.createListener({onResult,onStatus})`、`.load()`；音频回调里先判 `continuousLockUntil` 和 `window.__answerMuteUntil` |
| 主 → 手势 | `window.GestureEngine.start(video, canvas, onAnswer, onStatus)`、`.load()`；返回 `{stop()}` |
| 手势 → 主 | `onAnswer(dir, conf)` 里再走一次 `answer(dir)` |

语音是**经典脚本**（HTML 里 `<script src>` 直接引，首屏就下载 `voice/engine.js` 约 7.6 KB，但不加载模型），
手势是**动态 import**（module 脚本首屏就 import `gesture/engine.js` + `vendor/vision_bundle.mjs` 共约 145 KB，
WASM 和 `hand_landmarker.task` 才在 `load()` 时下载）。

所以准确说法是：**首屏不会下载任何模型**（Vosk 43.8 MB / MediaPipe 7.5 MB + 19 MB WASM），
但两段封装代码本身是随首屏加载的。默认不请求麦克风和摄像头权限。
若要连封装代码都懒加载，得把 module import 挪进 `load()` 里（现在没这么做，因为要等 ESM 就绪的复杂度不值得）。

## 7. 事件绑定方式

全部交互走**一个委托监听器**（1649）：

```js
document.addEventListener('click', e => {
  const t = e.target.closest('[data-go],[data-action],[data-start],[data-calib],[data-ans],[data-near],[data-dist]');
  ...
});
```

所以「按钮长得像但点了没反应」= `data-*` 属性没写全，或不在这个选择器列表里。
新增按钮时**必须**把它的 `data-*` 加进 `closest()` 的选择器，否则委托不到。
（近距 33/40/45 cm 曾经因为把监听器一次性绑在旧节点上，移动 HTML 后失效过 —— 现在统一走 `data-near`。）

### P0 — 影响可用性，建议优先修

| # | 问题 | 位置 | 现象 | 建议 |
|---|---|---|---|---|
| 1 | **手势开关可能永久卡在「正在加载」** | `ensureGestureEngine()` 783，`{once:true}` 等 `vs-gesture-engine-ready` 事件，**无 reject、无超时** | 老 WebView 不支持 `type="module"` 或 `gesture/engine.js` 404 时，点开关后永远没反应，连提示都没有 | 加 8 秒超时 → `toast('手势模块加载失败')` 并把开关复位 |

## 10. 浏览器兼容与无障碍风险

### 10.1 兼容门槛（和「老旧 Android WebView」的目标冲突）

| 用了什么 | 最低要求 | 风险 |
|---|---|---|
| `?.` 可选链（1638、1768、1844、1861） | Chrome 80 / Safari 13.1 | 老 WebView 直接语法错误 → **整段内联脚本不执行，页面全白** |
| `<script type="module">`（1911） | Chrome 61 / Safari 11 | 老 WebView 不执行，且**没有 `nomodule` 兜底**，手势静默不可用 |
| CSS `inset`（45、179、206） | Chrome 87 | 老 WebView 布局塌 |
| CSS `aspect-ratio`（244） | Chrome 88 / Safari 15 | 语音试音方块变形 |
| `overscroll-behavior`（39） | Safari 16 | iOS 上页面回弹 |
| `navigator.wakeLock`（1626） | Chrome 84 / Safari 16.4 | 已有 try/catch，失败不影响功能 |

**建议**：加一段极早期探测（`<script>` 里 `if (!('replace' in String.prototype)) document.write(...)` 之类），
老浏览器直接显示「请用 Chrome / Safari 打开」，而不是白屏。

### 10.2 无障碍

| 问题 | 位置 |
|---|---|
| `user-scalable=no` 禁掉双指缩放，WCAG 1.4.4 不达标；iOS 会忽略、Android 生效 → 两平台不一致 | 5 |
| 字号用 `px`/`vw` 而不是 `rem`，**系统「大字号」设置完全无效**（而目标用户正是老花人群） | 32、71-73；`#hud` `.82em`≈14 px、`#gesturePip .lbl` 11 px |
| 热区 < 44 px：`#btnPause` 40 px、`.calib-handle` 40×40 | 176、109-112 |
| `.verify-tile` 默认态 `#9aa3af` on `#fff` ≈ **2.6:1**，大字号要求 3:1 —— 试音页的方块几乎看不见 | 238 |
| 4 个开关只有 `role="switch"` + `aria-checked`，**没有可访问名** | 524、530、537、542 |
