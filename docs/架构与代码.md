## 1. 整体形状

```
index.html                  一个文件装下 CSS + 10 个页面 + 全部业务逻辑（1869 行）
├── <style>                 8 – 295    设计变量 + 组件 + 各页面样式
├── <!-- 页面 -->            299 – 563  10 个 <section class="screen" data-screen="…">
├── <script src="voice/engine.js">  564  经典脚本，挂 window.VoiceEngine
├── <script>                565 – 1859 全部业务逻辑（16 个分区，见下）
└── <script type="module">  1860 – 1865 只做一件事：import 手势模块并挂 window.GestureEngine

voice/engine.js   语音模块封装（Vosk WASM、VAD、16 kHz 单音语法），218 行
gesture/engine.js 手势模块封装（MediaPipe Hand、骨架绘制、预览框跟随比例），157 行
gesture/hand_rules.js    21 点 → 上/下/左/右（104 行）
gesture/gesture_gate.js  动作激活 / 保持 400 ms / 每题一次 / 冷却
tools/*.py        syntax_check.py（内联脚本语法自检）、check_links.py（markdown 链接检查）、cap_table.py（上限表）
shots/            界面截图，README 引用全部 10 张
```

`icon-192.png` 只当浏览器标签页图标用；**没有 manifest、没有 Service Worker**（PWA 已在 v0.9.6 移除）。

### 3.3 `session` 字段

```js
session = {
  type,            // 'distance' | 'near'
  distM,           // 米
  eyes: [...],     // 远距两只眼、近距只测双眼
  eyeIdx,          // 当前眼
  cap,             // maxRenderableIndex(distM)，本机上限档位
  group,           // 第几组（显示在 HUD）
  trials,          // 总题数
  results: {},     // { right|left|both: { logMAR, decimal, snellen, atCap, worse } }
  continuousMode,  // 语音/手势开着 → 每题后 1 秒缓冲
  trialsLog: [],   // 逐题明细，直接进历史
  aborted, paused,
  // 运行期：
  resolve,                 // 当前题的作答 Promise 回调
  questionShownAt,          // 出题时间（250 ms 内不接受作答，防抢答）
  continuousLockUntil,      // 1 秒硬缓冲截止时间
  lastRender,               // { size }，?debug=1 时显示视标像素尺寸
}
```

### 3.4 历史记录结构

```js
{ ts, type,
  results: { right|left|both: { logMAR, decimal, worse, atCap } },
  trials,
  log: [ { eye, group, level, dir, ans, correct, at } ]   // 逐题明细（v0.9 起才有）
}
```

## 4. 一次测试的数据流

```
点击「开始测试」(data-action="setup-start")
  └─ startSession()                       ← 建 session、算 cap、开唤醒锁、按设置启动语音/手势
       ├─ showScreen('test')                ← 显示答题条
       └─ for 每只眼:
            ├─ countdown(3,2,1) + speak()   ← 「右眼测试，请遮住左眼」
            ├─ runEye()
            │    ├─ runLevel(level)         ← 一组 5 题
            │    │    ├─ pickDir() → drawOptotype(dir, level)   ← 画视标，记录 questionShownAt
            │    │    └─ getAnswer()        ← SIM 模式：simulateAnswer()；真实模式：waitAnswer()
            │    │         └─ answer(dir)   ← 唯一作答入口：闪按钮、开 1 秒锁、resolve
            │    │    └─ 答完 1 秒缓冲（continuousMode 时）→ answerGap()
            │    ├─ 通过（对 4）→ level += 2（封顶到 cap）
            │    └─ 失败 → 首次记 firstFail，退到 F-1 复测；再失败定档 F-2
            └─ intermission()            ← 换眼，5 秒倒计时自动继续
       └─ finishSession()
            ├─ 写 vs.history（含逐题 log）
            ├─ renderResult()            ← 三种记法 + 分级 + 建议
            └─ speak('测试完成…')
```

**关键契约**（改动时别破坏）：

- `drawOptotype()` 是唯一决定视标物理尺寸的地方，它同时写 `session.lastRender`。
- `answer()` 是**唯一**作答入口：点击、滑动、键盘、语音、手势全部走它，所以 1 秒锁和按钮闪烁只写一遍。
- `runLevel()` 只返回 `{pass}` / `{aborted}`；定档逻辑全在 `runEye()`。
- `session.cap` 在会话开始时算一次，整个会话不再变。

## 6. AI 模块接入点

| 方向 | 入口 |
|---|---|
| 主 → 语音 | `window.VoiceEngine.createListener({onResult,onStatus})`、`.load()`；音频回调里先判 `continuousLockUntil` 和 `window.__answerMuteUntil` |
| 主 → 手势 | `window.GestureEngine.start(video, canvas, onAnswer, onStatus)`、`.load()`；返回 `{stop()}` |
| 手势 → 主 | `onAnswer(dir, conf)` 里再走一次 `answer(dir)` |

语音是**经典脚本**（HTML 里 `<script src>` 直接引，首屏下载 `voice/engine.js` 约 7.6 KB，不加载模型），
手势是 **module import**（首屏就 import `gesture/engine.js` + `vendor/vision_bundle.mjs` 共约 145 KB，
WASM 和 `hand_landmarker.task` 才在 `load()` 时下载）。

准确说法：**首屏不下载任何模型**（Vosk 43.8 MB / MediaPipe 7.5 MB + 19 MB WASM），
但两段封装代码本身随首屏加载。默认不请求麦克风和摄像头权限。

`GestureEngine.load()` 只认 **1 只手**（`numHands: 1`）：老人单手作答，省一半算力。

## 7. 事件绑定方式

全部交互走**一个委托监听器**（1606）：

```js
document.addEventListener('click', e => {
  const t = e.target.closest('[data-go],[data-action],[data-start],[data-calib],[data-ans],[data-near],[data-dist]');
  ...
});
```

「按钮长得像但点了没反应」= `data-*` 属性没写全，或不在这个选择器列表里。
新增按钮时**必须**把它的 `data-*` 加进 `closest()` 的选择器。
（近距 33/40/45 cm 曾因为监听器一次性绑在旧节点上，搬 HTML 后失效过 —— 现在统一走 `data-near`。）

## 9. 已知问题清单（2026-11-08 全量审计，v0.9.6 已清掉一批）

按「会不会让老人用不下去」排序，不是按代码味道排序。

### P0 — 影响可用性，建议优先修

| # | 问题 | 位置 | 现象 | 建议 |
|---|---|---|---|---|
| 1 | **手势开关可能永久卡在「正在加载」** | `ensureGestureEngine()`（760）用 `{once:true}` 等 `vs-gesture-engine-ready`，**无 reject、无超时** | 老 WebView 不支持 `type="module"` 或 `gesture/engine.js` 404 时，点开关后永远没反应 | 加 8 秒超时 → `toast('手势模块加载失败')` 并把开关复位 |

## 10. 浏览器兼容与无障碍风险

### 10.1 兼容门槛（和「老旧 Android WebView」的目标冲突）

| 用了什么 | 最低要求 | 风险 |
|---|---|---|
| `?.` 可选链 | Chrome 80 / Safari 13.1 | 老 WebView 直接语法错误 → **整段内联脚本不执行，页面全白** |
| `<script type="module">` | Chrome 61 / Safari 11 | 老 WebView 不执行，且**没有 `nomodule` 兜底**，手势静默不可用 |
| CSS `inset` | Chrome 87 | 老 WebView 布局塌 |
| CSS `aspect-ratio` | Chrome 88 / Safari 15 | 语音试音方块、摄像头预览框变形 |
| `overscroll-behavior` | Safari 16 | iOS 上页面回弹 |
| `navigator.wakeLock` | Chrome 84 / Safari 16.4 | 已有 try/catch，失败不影响功能 |

**建议**：加一段极早期探测，老浏览器直接显示「请用 Chrome / Safari 打开」，而不是白屏。

### 10.2 无障碍

| 问题 | 位置 |
|---|---|
| `user-scalable=no` 禁掉双指缩放，WCAG 1.4.4 不达标；iOS 会忽略、Android 生效 → 两平台不一致 | `<meta viewport>` |
| 字号用 `px`/`vw` 而不是 `rem`，**系统「大字号」设置完全无效**（目标用户正是老花人群） | `--fs` 及 `.82em`/`11px` 等处 |
| 热区 < 44 px：`#btnPause` 40 px、`.calib-handle` 40×40 | CSS 测试屏 / 校准页 |
| `.verify-tile` 默认态 `#9aa3af` on `#fff` ≈ **2.6:1**，大字号要求 3:1 —— 试音页方块几乎看不见 | CSS 语音/手势段 |
